## What this is

tubedrop is a small **local web UI for downloading YouTube videos/audio on a Mac**: paste a link, pick a quality, get an MP4 or MP3.
It runs a stdlib-only Python HTTP server on `127.0.0.1` that drives [`yt-dlp`](https://github.com/yt-dlp/yt-dlp) + `ffmpeg` and opens a single-page UI in the browser.
It started from the terminal tool [kaifcodec/ytconverter](https://github.com/kaifcodec/ytconverter) (MIT) — this repo keeps its git history and the `ytconverter` package name, but the upstream CLI code has been removed; only the web UI remains.
Personal open-source project of [@RebSem](https://github.com/RebSem); released as GitHub Releases v1.0–v1.3 (May 2026). Target platform: macOS (the installer and folder picker are macOS-only).

HTTP API (all in `web/server.py`, class `Handler`):
- GET: `/` (UI), `/api/defaults`, `/api/pick-folder` (AppleScript folder dialog), `/api/browsers`, `/api/events/<job_id>` (Server-Sent Events progress), `/api/reveal?path=…` (show file in Finder via `open -R`).
- POST: `/api/inspect` (metadata + qualities + size estimates), `/api/download`, `/api/connect-browser`, `/api/disconnect-browser`, `/api/quit`.

## Commands

From the repo root. Python **3.10+** is required (yt-dlp dropped 3.9).

```bash
# End-user install (macOS): downloads Python/ffmpeg if needed, writes ~/Desktop/Tubedrop.command
./install.command

# Developer setup without the installer
python3 -m venv .venv
.venv/bin/pip install --upgrade --pre "yt-dlp[default]"   # what install.command installs
# ffmpeg must be on PATH (or in .bin/ffmpeg, which Tubedrop.command puts on PATH) — the server refuses to start without it

# Run
.venv/bin/python -m ytconverter                  # starts server, opens the browser
.venv/bin/python -m ytconverter --no-browser --port 8799
.venv/bin/python -m ytconverter --help
curl -X POST http://127.0.0.1:8765/api/quit      # stop a running server (same as the Quit button)

# Sanity check (there is no test suite on main)
.venv/bin/python -m compileall -q ytconverter
```

Verified on 2026-10-11 (Python 3.14.7, `pip install yt-dlp` → 2026.08.19, Homebrew ffmpeg on PATH): `python -m ytconverter --help`, `python -m compileall -q ytconverter`, starting the server with `--no-browser --port <n>`, `GET /` → 200, `GET /api/defaults` → JSON, `POST /api/quit` → clean shutdown.
On the `wip/2026-10-11` tree: `python -m unittest discover -s tests -t .` → 43 tests OK, `python -m ytconverter --help` shows `--no-update`.
**Not run:** `install.command` (downloads binaries and writes to `~/Desktop`), real downloads (network/YouTube), the `promo/` Remotion build.

## Configuration

- **No env vars on `main`.** (`PYTHONWARNINGS` is set to `ignore` by the app itself.) On `wip/2026-10-11`: `TUBEDROP_NO_UPDATE` (any value) disables the daily yt-dlp update.
- **CLI flags:** `-W/--web` (default, the only mode), `--port` (default 8765; if busy, the following ports are tried, 20 in total), `--no-browser`.
- **`.tubedrop.config`** (repo root, JSON, gitignored) — `{"cookies_browser": "<safari|chrome|brave|edge|firefox>"}` set by the HD-unlock modal; when present, yt-dlp gets `cookiesfrombrowser`.
- Runtime files in the repo root (gitignored): `.tubedrop.pid`, `.tubedrop.url` (used by `Tubedrop.command` to reuse a running instance), `.venv/`, `.bin/` (`ffmpeg`, optional `python/`), `Tubedrop.command`.
- Default download folder: `~/Downloads/tubedrop` (created on first download); folder presets: Downloads, Desktop, Movies, Music.
- **No secrets.** Browser cookies are read locally by yt-dlp only after the user opts in; nothing is stored in the repo.

## Deploy & release

- No server, no CI. Users get the code by downloading `main` as a zip (README link `archive/refs/heads/main.zip`) and double-clicking `install.command` — **whatever is on `main` is what new users install**.
- Releases are git tags `vX.Y` + GitHub Releases with hand-written notes (v1.0–v1.3, 2026-05-18 … 2026-05-20). `pyproject.toml`'s version has not been kept in sync.
- Not published to PyPI (the `ytconverter` PyPI package is upstream's, not this project).

## Conventions

- Python, stdlib only on the server side (`http.server`, `threading`, `json`, …); **`yt-dlp` is the only runtime dependency** — keep it that way unless the owner agrees.
- UI is a single string in `web/ui.py`: vanilla JS, no framework, no build step; JetBrains Mono from Google Fonts with SF Mono fallback; light + dark theme. UI strings are **English**.
- Installer: no Homebrew, no `sudo`, nothing global — everything inside the project folder (`.venv/`, `.bin/`); deleting the folder uninstalls.
- Commit messages: release commits are `vX.Y: short summary` with a long explanatory body (what broke, why, what changed per area: UI / Backend / README); docs-only commits use `docs: …`. Commits are co-authored with Claude (`Co-Authored-By:` trailer).
- Docs language: English.
- Testing expectation: there is no test suite on `main`; when changing format/quality logic, test manually against real videos (and see the wip branch's `tests/` for the direction the project is taking).

## Rules / what must not break

- **Keep upstream attribution:** `LICENSE` (MIT, KAIF_CODEC) and the README credits to kaifcodec/ytconverter, yt-dlp, ffmpeg.
- Server binds to **`127.0.0.1` only** — never `0.0.0.0` (it can read browser cookies, reveal files and open dialogs).
- **Cookie access is opt-in.** Never read browser cookies unless the user connected a browser (`.tubedrop.config`); keep the "cookies never leave your Mac" promise true.
- Do not re-add a hardcoded yt-dlp `player_client` (v1.3 removed `["default", "web_safari"]` because YouTube started rejecting it).
- `install.command` must stay re-runnable, Homebrew-free and sudo-free, and must keep generating `Tubedrop.command` (the Desktop launcher depends on `.tubedrop.pid` / `.tubedrop.url`).
- The package directory must stay named `ytconverter` (`python -m ytconverter`, `[tool.flit.module]`, generated launchers all depend on it).
- Don't merge or rewrite `wip/2026-10-11` without the owner — it is the only copy of months of work.
- Personal use only; respect the YouTube Terms of Service (README footer).

## Gotchas

- `main` and `wip/2026-10-11` share no tubedrop commits (see Current state) — don't assume `git log main..wip` shows only the new work; compare trees with `git diff main origin/wip/2026-10-11` instead.
- The server refuses to start if `ffmpeg` is not on `PATH` (`_preflight`). `Tubedrop.command` prepends `.bin/` to `PATH`; when running `python -m ytconverter` by hand, put ffmpeg on `PATH` yourself.
- The server writes state into the **repo root** (`_repo_root = parents[2]` of `web/server.py`): `.tubedrop.pid`, `.tubedrop.url`, `.tubedrop.config`. Running from an installed wheel would write next to site-packages — the app is designed to run from a checkout.
- `install.command` deletes and recreates `~/Desktop/Tubedrop.command` and pins `REPO_DIR` to the folder it was run from — moving the folder breaks the launcher until you re-run the installer.
- The `.gitignore` has a blanket `*.txt` rule inherited from upstream — a new `requirements.txt` or notes file would be silently ignored.
- Cookie paths are macOS-specific (`~/Library/...`); Safari's store moved into `~/Library/Containers/com.apple.Safari/...` on macOS 14+, both are checked. `_detect_browsers()` returns nothing on non-macOS.
- YouTube changes often: if downloads break or fall back to 360p, first upgrade yt-dlp (`.venv/bin/pip install -U --pre "yt-dlp[default]"`) before changing code.
